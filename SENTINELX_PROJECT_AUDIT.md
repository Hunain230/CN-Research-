# SentinelX project audit

**Scope:** Read-only repository and saved-artifact audit, 15 November 2026. This report records what exists; it is not a new experiment, a model evaluation, or an operational validation. The supplied Phase 03 and FINAL PDFs describe requirements and methodology, not evidence that each component has been implemented. No source, data, model, or frozen result was changed for this audit.

## 1. Current architecture and execution flow

The project has two related tracks. The **offline empirical track** ingests Microsoft GUIDE_Test locally, quarantines ambiguous alert keys, constructs same-organization candidate pairs from descriptor, entity, and time signals, scores pairs, forms predicted incident groups, scores those groups, freezes predictions, and evaluates them in a separate evaluator against expert incident memberships and top-20 queue labels. The strongest saved descriptive configuration is entity proposals + v2 pair grouping + v7 group ranking. This is retrospective research on previously accessed labels.

The **C/P/V track** is a deterministic synthetic demonstration of Correlate → Prioritize → Verify, with a local Qwen pilot on a bounded sample. It is not the model that produced the 499-queue v2/v7 results. The static dashboard replays fictional events and an earlier aggregate research view. It is not a connected SOC console.

Typical entry points are [`src/cli.py`](src/cli.py) for phase checks and preprocessing, [`src/submission_entity_time_shards.py`](src/submission_entity_time_shards.py) for local evidence projections, [`src/submission_entity_time_pair_v2.py`](src/submission_entity_time_pair_v2.py) for pair training/prediction/evaluation, [`src/submission_descriptor_ranker_v7.py`](src/submission_descriptor_ranker_v7.py) for group ranking, [`src/submission_full_guide.py`](src/submission_full_guide.py) and [`src/offline_joint_comparison.py`](src/offline_joint_comparison.py) for offline evaluation, [`src/mvp_demo.py`](src/mvp_demo.py) for the fictional C/P/V run, and [`run_submission_suite.ps1`](run_submission_suite.ps1) for the wider local suite. Frozen run directories and their manifests are under [`outputs/`](outputs/); some private derived stores under `data/derived/` are ignored by Git.

The candidate generator uses within-organization postings and bounded neighbors, including a 48-hour entity route and a one-hour technique route. The v2 histogram-gradient-boosted pair model uses descriptor overlap, entity type/rarity, time gap, and route signals; its threshold was selected on development organizations. Training/evaluator labels are separate in the code path, but the GUIDE_Test labels were previously seen during project development.

## 4. Implementation versus the proposed C/P/V methodology

The original [`FINAL methodology PDF`](FINAL%20%281%29%20%281%29.pdf) calls for Agent C to return LINK/NO_LINK/UNSURE with evidence references; Agent P to score and explain predicted incidents with supporting and contradicting evidence; and an independent Agent V to check citations, return PASS/REVISE/REVIEW, allow one revision, then route unresolved cases to analysts. It also proposes matched B0–B4 comparisons, robustness perturbations, and reviewer-support measurement. The [`Phase 03 PDF`](Phase%2003%20-%20Implementation%20%281%29.pdf) requests implementation and comparative analysis. Their requirements are not proof of completion.

## 5. Research and engineering weaknesses

1. **Three separate recall losses.** The candidate graph's optimistic incident-connectivity bound is 86.55%; v2's existing-group oracle bound is 69.83%; v7 achieves 49.82% in top 20. Candidate routes, group purity/completeness, and ordering all matter. Lowering a pair threshold alone can create false merges. The v2 model's 90.41% pair precision comes with only 0.1695% exhaustive positive-pair recall; both denominators must be reported.
2. **Candidate and grouping limitations.** Bounded neighbor postings and time windows can miss relations; connected components can chain an erroneous edge into an impure group. There is no proven group-level merge improvement: the later bridge/merge explorations did not replace the frozen v2 baseline. An oracle connectivity ceiling does not show that a learnable, purity-preserving linker can reach it.
3. **Ranking limitations.** The 69.83% existing-group ceiling leaves roughly 20 percentage points between oracle ordering and v7 on the same groups. The v7 blend uses identity-heavy features and development-selected weights; singleton and hard-negative ordering remain plausible failure modes. Its 135-queue figure is outside fitting, not untouched confirmation.
4. **Data provenance and leakage.** `IncidentId`, expert ranks, grades, and outcomes belong only in the evaluator; the policy files enforce an intended boundary, but previously accessed GUIDE_Test labels mean repeated selection on these results risks post-exposure bias. About **70,702 conflicting `(OrgId, AlertId)` keys** are excluded; **855 expert labels** have only ambiguous evidence. There is no authoritative prediction-independent disambiguation rule. Source records do not establish entity/time availability at alert creation, and the official operational model-field allowlist is empty. Local exploratory permission is not production approval. See [`point-in-time evidence status`](submission/POINT_IN_TIME_EVIDENCE_STATUS_20261114.md).
5. **Evaluation and robustness.** The 499 queues are a broad retrospective descriptive run, not a fresh test. The methodology's full matched C/P/V baselines, evidence ablations, reviewer-support outcomes, and live shadow-mode study remain open. Pairwise, group, and top-20 metrics answer different questions; ordinary binary ROC-AUC/FPR tables from traffic classification would be misleading as direct comparisons.
6. **Explainability, evidence verification, and performance.** Synthetic traces demonstrate reference formatting but do not validate real incident-level citations. Qwen calls are slow on the local pilot (roughly 27-second median and 44-second 95th percentile per recorded call); the offline batch runtime is not alert-to-decision latency. The local system has files, SQLite evaluator data, DuckDB/Parquet projections, and an Ollama client, but no production API, analyst database, persistent review decisions, access control, or monitored streaming path.

## 8. Recommended development roadmap

1. **Protocol and data gate.** Reconcile the v2 `cap100` contract mismatch and choose the exact group/ranker configuration before a new study. Document alert-time availability, authorized fields, and an independent ambiguous-key rule. Obtain an untouched cohort or keep all GUIDE_Test conclusions exploratory.
2. **Offline component study.** With a legitimate development set, freeze the current v2+v7 descriptive reference. Change one candidate route, grouping rule, or ranking rule at a time; preserve matched alert and label denominators, purity, false merges, cost, and runtime. Do not tune on previously accessed GUIDE_Test labels and call the result confirmatory.
3. **Methodology completion.** Implement empirical C/P/V citation and revision behavior with the same input and budget constraints as B0–B4; separate agent effects from candidate/group/ranker effects. Add missing/conflicting evidence tests and an independent verifier audit.
4. **Prospective freeze and evaluation.** Register source hashes, parameters, field policy, cohorts, metrics, and analysis before opening new labels. Evaluate once on the untouched cohort; report confidence intervals and negative results. If no new cohort exists, publish the existing numbers explicitly as exploratory.
5. **Exhibition then operations.** Verify the interactive demo and mark fictional scenes clearly. A later approved shadow-mode SOC study is needed to measure alert-to-decision latency, analyst corrections, workload, and real workflow utility.

## 9. Risks and constraints

- The **official operational feature allowlist is empty**. Local entity/time sensitivity experiments do not authorize production use; the dataset does not prove arrival-time availability for those fields.
- **GUIDE_Test labels were accessed previously**. A training-disjoint split inside the project is not an untouched test after repeated analysis. The saved 49.82% result is reproducible and descriptive, not an unbiased acceptance estimate.
- Ambiguous alert identities, source rank semantics, and the 80% recovery rule affect the denominator and interpretation. Preserve all exclusions, tie handling, and evaluator boundaries in future comparisons.
- The 69.83% and 86.55% figures are **oracle ceilings** under different assumptions. They are not achieved model recall or guaranteed attainable targets.
- The local Qwen pilot, synthetic C/P/V demo, static dashboard, and offline statistical run are distinct artifacts. Combining their best figures into one implied end-to-end operational result would overstate the evidence.
- Existing source and output artifacts, including previously modified working-tree files, were left untouched. Only this audit report was added.
